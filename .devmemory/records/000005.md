## Summary

Built out devmemory into the full 12-phase spec: migrations, decision status/supersession/conflict detection, EXTENDS/IMPLEMENTS/TESTS edges, node versioning, branch isolation, retrospective onboarding, traversal profiles, context compiler, MCP server, token-cost ROI reporting.

## Why

User was offered a smaller 'targeted hardening' option after a full audit against an aspirational 20-section spec, but explicitly chose the full build-out, with MCP prioritized and conflict detection extended to include LLM arbitration.

## Rejected alternatives

Smaller 'targeted hardening' scope (migrations+status+MCP+secrets+branch-isolation only, skipping versioning/onboarding/profiles/compiler/benchmark). Also rejected within the full build-out: vector/semantic search, a bespoke NL query planner inside devmemory, a heavyweight baseline-vs-devmemory benchmark/ablation suite, and full node/edge historical versioning for code (git already serves that role).
